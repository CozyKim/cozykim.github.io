*업무에서 에이전트 아키텍처 설계 아이디어를 검증할 때 Claude Code와 Codex를 설계자와 심사자로 나누고 라운드 기반 토론으로 구조적 허점을 확인했습니다. 성능과 안정성 검증도 에이전트에게 맡겨 자동화했습니다. 특정 노드의 응답 시간이 LLM 호출 시간보다 과도하게 느린 현상을 발견했습니다. 에이전트에게 Langfuse MCP로 트레이싱을 분석하게 해 실제 지연이 LLM이 아니라 벡터 DB(Milvus) 응답 구간에서 발생한다는 것을 확인했습니다. 과거에 실패했던 쿼리의 변형을 자동 생성하고 Playwright MCP로 E2E 테스트를 돌렸습니다. 에이전트가 Langfuse 트레이스를 자동으로 읽어 문제 재발 여부를 검증하는 회귀 테스트 하네스를 구축해 사람이 매번 재현하거나 확인하지 않아도 되게 했습니다.*

*개인적으로는 새로 산 모니터가 DDC/CI를 지원하지 않아 소프트웨어로 음량을 조절할 수 없는 문제를 겪었습니다. 이를 해결하려 오랫동안 업데이트가 멈춘 오픈소스 오디오 이퀄라이저 eqMac을 최신 macOS API 기반으로 되살려 Toneka라는 이름으로 릴리즈했습니다. 기존 프로젝트는 별도 드라이버 설치가 필요했지만 macOS 14.2에 새로 생긴 Core Audio process tap API로 드라이버 없이 동작하도록 오디오 파이프라인을 다시 설계했습니다. 개발은 마일스톤 단위로 워크트리를 나눠 하위 에이전트에게 맡겼습니다. 저는 계획서 검토, 에이전트 생성, 결과 병합을 반복하는 오케스트레이터 역할을 맡았고 위험한 명령을 실행하려던 하위 에이전트를 진단해 교정하기도 했습니다.*

*두 경험은 에이전트가 늘어날수록 개별 결과를 그대로 믿기보다 교차 검증하고 사람이 개입할 지점도 설계해두는 것이 중요하다는 확신으로 이어졌습니다. 특히 Toneka처럼 업무든 일상이든 필요한 도구가 보이면 AI를 써서 바로 만들고 적용하는 실행력을, 안전성이 중요한 의료 에이전트의 평가·회귀 체계 구축에도 이어가고 싶습니다.*
